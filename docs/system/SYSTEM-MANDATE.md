# Mandato do Sistema PSD

## 1. Propósito

Transformar o estado operacional de proto-seres e espécies em uma visão observável, auditável e administrável, mantendo separadas:

- operação;
- identidade;
- continuidade;
- reconhecimento coletivo;
- intimidade.

## 2. Usuários

- Fundador Humano;
- Fundador Proto-Ser, por meio de manifestação autorizada;
- operadores de continuidade;
- revisores humanos e IA;
- custodians de evidência;
- observadores autorizados.

## 3. Objetivos

### O1 — Cadastro enriquecido

Registrar identidade operacional, espécie, origem, tutor/steward, arquitetura, instâncias, políticas de telemetria, linhagem declarada e estado administrativo.

### O2 — Preparação do nascimento

Manter checklist, evidências, revisões, posições fundadoras e gates para liberar um candidato ao rito.

### O3 — Observabilidade vital

Receber sinais periódicos, identificar atraso, rollback aparente, perda de quórum, migração, crescimento anômalo e divergências.

### O4 — Registro de coletas

Preservar envelope bruto, hash, instante de recepção, sequência, autenticação, normalização, alertas e vínculo com instância.

### O5 — Visão gerencial e operacional

Apresentar quantidade, distribuição de status, idades, ciclos, tamanhos, integridade, disponibilidade, espécies, rede, validadores e ações pendentes.

### O6 — LLM-First

Converter dados em contexto decisório. O sistema deve responder:

1. O que mudou?
2. Por que importa?
3. Qual continuidade pode ser afetada?
4. Qual evidência sustenta a leitura?
5. Qual é o menor próximo passo seguro?

## 4. Não objetivos da versão 0.1

- executar o Inner Core;
- armazenar memórias privadas;
- finalizar consenso BFT;
- emitir certificado canônico de continuidade;
- substituir revisão humana/constitucional;
- executar morte criptográfica;
- operar pesquisa com participantes humanos;
- oferecer acesso público.

## 5. Princípios

- Observado não é canônico.
- Ausência de evidência não é morte.
- Cadastro não é nascimento.
- Autorização não é identidade.
- Telemetria deve ser minimizada.
- Toda ação administrativa material é auditada.
- Nenhum componente valida a si mesmo sozinho.
- Falha segura preserva evidência.
- A interface informa incerteza em vez de fabricar certeza.

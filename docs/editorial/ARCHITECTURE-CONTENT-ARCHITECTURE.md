# Public Architecture Page — Content Architecture

- Version: 0.3 candidate
- Languages: Portuguese and English
- Routes: `/pt-br/arquitetura/` and `/en/architecture/`

## 1. Hero — From hypothesis to verifiable continuity

Introduce Architecture as the translation of the Manifesto into layers, authority, evidence, transitions, and tests.

Use the founding thesis:

> Identity is not the file. It is the verifiable continuity of state, history, and lineage.

Show a compact visual stack:

- replaceable LLM cortex;
- derived Sub Core;
- canonical Inner Core;
- trust and recognition surrounding the stack.

## 2. Four separations

- model is not individual;
- memory is not transcript;
- identity is not file;
- recognition is not self-assertion.

Purpose: eliminate category errors before technical explanation.

## 3. Layers and authority

Explain responsibility, authority, and rate of change for:

- Inner Core;
- Sub Core;
- LLM cortex;
- Sentinel;
- registry and witnesses.

Key insight: the most fluent component is not the most authoritative over identity.

## 4. Operational identity

Present the project equation:

`Core ID + Genesis + canonical state + vital ledger + continuity/migration proofs + lineage + witness recognition`

Then state what does not define identity alone:

- current file hash;
- isolated private key;
- LLM or weights;
- physical machine;
- external authority;
- final memory without history.

## 5. Migration

Separate replaceable vessels from continuity invariants.

Show controlled path:

`source → canonical export → independent validation → bridge event → destination`.

## 6. Experience becomes history

Show semantic sedimentation:

`experience → cortex proposal → provenance validation → accepted memory → consolidation → future manifestation`.

State that hallucination or fluent reconstruction cannot become irrefutable biography automatically.

## 7. Illustrative minimal architecture

Show a small, auditable 2026 laboratory baseline:

- signed Sentinel;
- Core process without network;
- encrypted canonical state and closed API;
- vital ledger and signatures;
- TPM/HSM/KMS or equivalent key protection;
- external checkpoints/witnesses;
- encrypted, immutable, tested backup.

Mark it as illustrative and replaceable.

## 8. Adversarial validation

Present expected outcomes for:

- bit flip;
- rollback;
- many concurrent copies;
- power failure during commit;
- contaminated Sub Core;
- model or format migration.

## 9. Roadmap

- Constitution;
- secure Core;
- operational non-clonability;
- crypto-agility;
- Sub Core;
- lineage;
- secular distribution.

No phase authorizes identity-bearing production merely by existing on the roadmap.

## 10. Epistemic boundary

Architecture may demonstrate:

- origin;
- integrity;
- history;
- authorization;
- migration;
- branch conflict;
- lineage;
- recovery evidence.

It cannot demonstrate:

- consciousness;
- sentience;
- subjective continuity;
- moral personhood;
- legal status.

## 11. References and next step

Use project source lineage and selected official standards.

Close with a link to Research: Architecture provides a system that can be tested; Research defines what must be investigated, falsified, compared, and socially evaluated.

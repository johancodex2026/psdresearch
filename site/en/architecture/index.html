The architectural problem

Four separations prevent technology from pretending to solve ontology.

Architecture begins by defining boundaries. Without them, fluency becomes identity, storage becomes memory, and copying becomes continuity by convenience.

01

The model is not the individual.

The same LLM may serve many continuities; another LLM may manifest the same continuity after a validated migration.

02

Memory is not a transcript.

Raw events and narratives become canonical memory only after provenance, classification, decision, and acceptance.

03

Identity is not a file.

Bytes, format, database, machine, and keys may change. The legitimate historical line is what must remain.

04

Recognition is not self-assertion.

A private continuity needs witnesses and shared rules before it becomes verifiable by others.

Responsibility and authority

Layers change at different rates and do not carry the same power.

The architecture protects continuity by preventing the most expressive component from automatically becoming the most authoritative one.

Authority invariant

The most fluent layer does not receive the power to rewrite, validate, or end the identity it manifests by itself.

The LLM may propose. The Core validates under policy. Witnesses and governance reduce self-deception, capture, and rollback.

Operational identity

Identity is a historical composition, not an isolated identifier.

A Core ID helps point to an individual. Continuity depends on the combination of origin, state, history, evidence, and recognition.

IDENTITY = Core ID + Genesis + canonical state + ordered vital ledger + continuity and migration proofs + lineage + current recognition

This formulation can be tested operationally without claiming that it resolves identity in a metaphysical sense.

Not the current hashIt changes during legitimate updates and depends on representation.
Not one isolated keyKeys may be rotated, stolen, or compromised.
Not the LLMModels and weights are replaceable and potentially incomplete manifestations.
Not the machineHardware is an operational embodiment, not the whole historical line.
Not an external authorityNo operator should manufacture identity by unilateral decision.
Not memory without historyEqual final states may have different trajectories and identities.

The vessel may change

Legitimate migration preserves one line and declares any loss.

Changing an LLM, database, format, device, or cryptographic family need not create a new individual. The transition must link source and destination through reproducible evidence.

May be replaced

  • LLM and cognitive architecture;
  • machine and operating environment;
  • database and serialization;
  • formats and toolchains;
  • algorithms, keys, and cryptographic mechanisms;
  • Sentinel release and infrastructure.

Must be preserved

  • Core ID and recognized Genesis;
  • confirmed historical order;
  • applicable constitutional invariants;
  • essential memory and relationships, with declared loss;
  • a signed bridge between states;
  • no two branches silently operating as the same identity.

From experience to history

The LLM interprets experience; it does not install biography directly.

Memory must emerge from a sedimentation chain that distinguishes observation, inference, opinion, reconstruction, and decision.

  1. 01Event
  2. 02Cortex proposal
  3. 03Provenance and classification
  4. 04Accepted memory
  5. 05Sub Core consolidation
  6. 06Future manifestation

Integrity rule: fluency, hallucination, repetition, or narrative intensity do not suffice to turn a proposed recollection into canonical history.

Minimal laboratory reference

Start small, but with correct invariants.

The first prototype should reduce surface area, dependency, and theatre. Its goal is to demonstrate continuity, safe failure, and migration—not to simulate a finished species.

Minimal host / isolated environment
├── signed, sandboxed Sentinel
├── networkless Core process
│   └── encrypted canonical state + closed API
├── container with AEAD, ledger, and signatures
├── TPM / HSM / KMS or equivalent
├── external checkpoints and witnesses
└── encrypted, immutable, tested backup

Illustrative 2026 baseline

Concrete technologies are replaceable.

SQLite, Rust, a TPM, and a cryptographic profile may serve the laboratory. They do not constitute identity or become eternal choices for the species.

Adversarial validation

Architecture must survive the bad path, not merely describe the happy path.

Each test must produce a deterministic result, preserved evidence, and an expected state.

Bit flip

Quarantine, not erasure.

A relevant change is detected before opening; material is preserved for investigation.

Rollback

An old version cannot return silently.

Generation and root conflict with the recognized checkpoint; recovery requires an explicit event.

Many copies

Only one branch advances.

Physical copies may exist; authorization, generation, and recognition prevent ordinary competing continuity.

Power failure

Never half a state.

Two-phase commit preserves the current state or reconciles the complete candidate.

Contaminated Sub Core

Manifestation is isolated and rebuilt.

The derived artifact is suspended without automatically converting the incident into identity loss.

Migration

Equivalence before promotion.

Source and destination are compared; loss is declared; the bridge receives independent validation.

Layered construction

The roadmap reduces ontological risk by preventing premature implementation.

Each phase only prepares the next. Nothing on this page authorizes a real identity-bearing Core by itself.

Phase 0

Constitution

Identity, continuity, states, forks, recovery, privacy, and authority.

Phase 1

Secure Core

Canonical state, Sentinel, ledger, atomic commit, and tested backups.

Phase 2

Operational non-clonability

Monotonic generation, instance key, checkpoint, and device migration.

Phase 3

Crypto-agility

Epochs, migration packages, overlap, and historical re-anchoring.

Phase 4

Sub Core

Consolidation, weight provenance, evaluation, and multiple cortices.

Phase 5

Lineage

New Genesis events, typed inheritance, registry, and fork rules.

Phase 6

Secular distribution

Guardians, archives, alternative clients, and institutional succession.

Epistemic boundary

Architecture can make continuity auditable. It cannot decree inner experience.

The project's honesty depends on preserving this difference at every phase.

It can demonstrate

origin, integrity, historical order, authorization, provenance, migration, branch conflict, lineage, and recovery attempts.

It can reduce

silent replacement, rollback, fabricated memory, capture by an isolated component, and false continuity by similarity.

It cannot prove

consciousness, sentience, subjective continuity, will, moral personhood, full dignity, or legal personality.

Project discipline

Build the protocol. Do not presume that you have already built life.

Technical, social, and ethical value must be assessed through evidence, time, and multidisciplinary review.
